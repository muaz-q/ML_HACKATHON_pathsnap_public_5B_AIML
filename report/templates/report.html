Summary. For each GPS fix we generate the 12 nearest directed road arcs as candidates and compute 23 location-independent features per (fix, candidate) pair. A classifier estimates P(candidate = reference arc), and an HMM decoded with Viterbi turns these into a connected route using shortest-path distances on the directed road graph. Ten models were compared with trip-grouped 5-fold CV. LightGBM was selected and tuned with Bayesian optimisation (Optuna TPE). On the 10 student-test trips the final system reaches $hmm_top1_s observation-level Top-1 accuracy (classifier only: $clf_top1_s) and route arc F1 $hmm_f1_s (classifier only: $clf_f1). It is deployed as a FastAPI service (Laptop 1) with a Leaflet UI (Laptop 2).

2. Dataset Understanding and Exploratory Data Analysis

Partitions: all EDA uses train (80 trips) and student_test (10 trips). Evaluator trips were not available and were never used.

2.1 How did we preprocess the data?

  1. Loading and cleaning (pathsnap/data.py): read the four headerless files per trip; drop non-finite track rows, sort by timestamp, drop duplicate timestamps. The checks found 0 NaN rows, 0 invalid coordinates and 0 non-increasing timestamps in both partitions, but the steps are kept for unseen data.
  2. Projection: lon/lat are angular and the trips span every continent, so each trip is projected into a local azimuthal-equidistant frame (metres) centred on its GPS centroid (pyproj, always_xy because the files are lon-first). Distortion is <0.1 % at trip scale.
  3. Per-fix reference labels (pathsnap/labels.py): .route is an untimed arc sequence, not one row per fix. Each fix is assigned a route position by a monotonic dynamic-programming alignment minimising total point-to-arc distance, with D[t,j] = c[t,j] + minj'≤j D[t−1,j'].
  4. Reliability filter: fixes farther than 60 m from their aligned arc ($tr_gt60 train fixes, $tr_gt60_pct; $te_gt60 in student-test) occur where the track extends beyond the reference route (e.g. trip 54: $trip54_pct of its fixes). They are excluded from training and scoring.
  5. Candidates (pathsnap/features.py): a KD-tree over points sampled every 8 m along road segments near the track; the 12 nearest directed arcs per fix. Candidate miss rate on reliable fixes: $miss_train (train), $miss_test (student-test).

Missing-value analysis. There are no missing values at the field level. The "missing data" in this dataset is temporal: GPS gaps (up to ~42 h in trip 90) and fixes not covered by the reference route. Both are handled explicitly (the HMM gap logic and the reliability filter).

Observed patterns. (i) Every trip carries its own local network, and the trips are worldwide, so ids and absolute coordinates cannot be features. (ii) Two-way roads appear as two arcs with identical geometry, so distance alone cannot decide direction: the nearest-arc rule gets only $nn_top1 Top-1. (iii) Most fixes lie 4–8 m from their road. (iv) The networks are cut-outs with dangling edges and several components, so shortest paths can fail.

3. Model Experimentation and Comparison

Protocol. The task is binary classification of (fix, candidate) rows. Evaluation uses GroupKFold(5) by trip on the 80 training trips. Every model is fitted on the same 30,000-fix sample from the training folds; validation uses the full held-out fold (KNN: a 15,000-fix sample because of its O(train × query) cost). Each model is then refitted on a 30,000-fix sample of all training trips and scored on student-test. Seed 42. Primary metric: observation-level Top-1 accuracy (the argmax candidate is the reference arc), because it is the system's actual decision. Macro F1 uses the argmax decision per row (1 for the fix's argmax candidate, else 0). Log loss is computed on the raw probabilities. Route continuity is the share of consecutive fix pairs whose arcs are the same or reachable on the directed graph within max(300 m, 3 × step + 150 m). Non-learned reference (nearest arc): Top-1 $nn_top1, Macro F1 $nn_f1.

5. HMM and Viterbi Route Reconstruction

Q1. Hidden states: for each fix, its top K = $hmm_k candidate arcs by classifier probability, each with the fix's projected offset along the arc.

Q2. Emissions: log et(a) = we · log p̂(a | t), where p̂ is the classifier probability renormalised over the K candidates; we = $hmm_w.

Q3. Transitions: log A(a→b) = −|droute − dgps| / β, β = $hmm_beta m × max(1, √Δt) (Newson & Krumm). droute = remaining length of a + shortest path from head(a) to tail(b) + offset on b, or the offset difference on the same arc (backward moves <15 m are treated as jitter). Shortest paths come from a bounded Dijkstra (radius max(300 m, 3·dgps+150 m)) on the directed graph, cached per source node. Viterbi: δt(b) = et(b) + maxa[δt−1(a) + log A(a,b)], with back-pointers.

Q4. Missing candidates / large gaps: every fix has at least one candidate (the nearest arcs are taken regardless of distance). If Δt > 60 s or dgps > 2 km, the chain is broken: a uniform transition, restarting from the best previous score ($n_breaks breaks on student-test).

Q5. Disconnected segments: an unreachable pair gets a finite penalty log A = −$hmm_jump rather than −∞, so decoding never fails, and the decoded per-fix arcs are stitched into a continuous route by inserting shortest-path arcs where consecutive arcs are not adjacent.

Decoder tuning: a grid over β ∈ {3, 6, 10, 20}, we ∈ {0.5, 1, 2}, K ∈ {3, 4, 6, 8} on $n_tune_trips training trips using out-of-fold probabilities. $grid_text

7. API, UI and Deployment

Laptop 1 runs uvicorn api.main:app --host 0.0.0.0 --port 8000 with PATHSNAP_EVAL_DIR pointing at the evaluation trips. Endpoints: GET /trips, POST /predict {trip_id}, GET /health. The API loads the trip without its route, runs features → LightGBM → HMM → stitching, then reads the reference only to compute the metrics server-side. The reference is never returned. Laptop 2 serves ui/index.html (Leaflet), which lists the trips, sends the selected id, and draws the GPS, network and predicted routes with the metrics and timings. Every request is logged on Laptop 1 (REQUEST / RESULT lines).
